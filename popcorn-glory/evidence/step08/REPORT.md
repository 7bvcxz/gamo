# Step 08 — 처음 해 보는 블라인드 AI 플레이테스트 (#110, 2026-11-03)

> 이 문서의 1–5 점수는 **AI 대리 판단**이다. 사람의 즐거움이 아니고, 통계적으로 유효한 재방문 지표도 아니다.
> 소유자(사람) 점수 칸은 소유자가 해 보고 넣기 전까지 비어 있다.

## 1. 어떻게 했나

| 항목 | 값 |
|---|---|
| 플레이어 | 실행마다 **새 에이전트**(새 컨텍스트) 하나. 이 대화의 기억·이슈·설계·소스 없음. 한 에이전트는 실험 **하나**만 했다 — 그래서 A·B·C 순서 효과는 없다(순서를 돌릴 대상이 없음) |
| 받은 것 | `tools/blind/README.md`의 플레이어 프롬프트 원문 하나: "처음 보는 폰 게임을 3분 해 보고 생각을 말하라" + 화면 명령 7개(`look`·`tap`·`hold`·`drag`·`wait`·`note`·`status`). 게임 이름·조작법·목표·경제 공식은 주지 않았다 |
| 화면 | 공개 URL(`https://7bvcxz.github.io/gamo/popcorn-glory/#click`·`#perfect`·`#explosion`)을 연 실제 Chromium. 400×860 CSS px, DPR 1.5(스크린샷 600×1290), 터치 입력, 소리 켬(AI는 들을 수 없다) |
| 입력 | 플레이어가 고른 픽셀 좌표로 실제 터치(CDP `touchStart`/`touchEnd`). 게임 상태를 읽거나 개발용 호출을 쓰지 않는다 — 브릿지의 `dev_*`는 `?dev=1` 없이는 없다 |
| 시간 | 플레이어의 첫 명령부터 **실제 3분**(생각하는 시간도 흐른다). 끝나면 도구가 "Time is up"만 답한다. 게임은 늘 보이는 탭이었고, 활동 시계는 끝에 200–229초였다(페이지가 열린 뒤 첫 명령까지 35–45초 포함) |
| 초기 조건 | 매번 새 페이지(저장 없음 → 돈 0, 단계 0), 같은 크기·같은 소리 설정 |
| 기록 | 컨트롤러가 플레이어 몰래: 모든 명령의 시각·인자·메모·그때 본 스크린샷(`actions.jsonl`), 5초마다 게임 상태(`state.jsonl`), 게임 자신의 기록(`game_log.json`), 화면 녹화(`screen.mp4`, 원본 webm을 300px·10fps로 줄임), 페이지 오류 |
| 평가자 | 이 개발 세션(게임을 만든 쪽 — **편향이 있다**). 원본 관찰을 고치지 않고 읽었다 |

### 블라인드는 지켜졌나 — 지시 + 사후 감사

에이전트는 기술적으로는 파일을 읽을 수 있었다(샌드박스가 아니다). 그래서 **블라인드는 지시로만 강제됐다.** 대신 여섯 플레이어의
대화 기록을 직접 읽어 **모든 도구 호출**을 감사했다(`tools/blind/audit.py`, 결과 `blind_audit.txt`):

- 6명 모두 `play.mjs` 명령과 **자기 스크린샷 읽기** 외의 호출이 **0건**이다. 일부는 `| tail -1`·`| grep`으로 도구의 출력만 걸렀다(파일을 읽지 않음).
- 감사가 실제로 잡는지 대조군으로 확인했다: 소스 파일을 `cat`하고 README를 읽는 가짜 기록, `head notes.txt` 하나짜리 가짜 기록은 모두 걸렸다.
- 플레이어 도구는 이름을 숨기려고 중립 경로(`scratchpad/phone/play.mjs`)에 복사했다. 게임 이름은 화면에 글로 나오지 않는다.

## 6. 해결할 마찰 (실행 가능한 것, 많이 나온 순)

1. **A·C 업그레이드 사이의 반복**(4/4명): "같은 탭 약 20번", "8탭이 일처럼", "기다려도·눌러도 달라지는 것이 없다". 한 가지 손동작과 업그레이드
   한 줄뿐이라는 것이 이유로 나왔다. → **Step 09의 핵심 질문**(재미의 구조이지 UI 장애가 아니다. 이 step에서 고치지 않았다).
2. **B의 발견**(2/2): 1차는 우연, 2차는 1분 반. 남은 혼란은 고리의 방향과 색이다(파랑 0.35 → 회색으로, 빨강 0.35 → 주황으로 읽힘. 주황을
   '데우는 중'으로 읽었다). 일부는 정지 화면 도구의 한계다. → Step 09에서 B를 고르면 첫 판의 안내를 다시 본다.
3. **업그레이드가 무엇을 주는지 미리 알 수 없다**(2명). 실루엣은 보이지만 효과(+1/탭, 두 배)는 사 보고서야 안다.
4. **다시 시작 아이콘이 두렵다**(4명이 일부러 누르지 않았다). 우발적인 다시 시작은 0번 — 두려움이 실제 손실로 이어지지는 않았다.
5. 작은 것: 대기 고리의 뜻(2명), 희미한 +N(1명), 바닥의 팝콘을 주울 수 있을 것 같다(1명), 화면 아무 데나 눌러도 된다(3명이 알아챔 — 의도한 것).

모든 실행에서 가장 일관된 좋은 점(AI 관찰): **글 없는 업그레이드 카드**(차오르는 노랑 → 금색 + 빨간 화살표, 6/6이 설명 없이 "지금 사라"로 읽음)와
**업그레이드마다 눈에 띄게 바뀌는 기계**(6/6이 좋았던 것으로 꼽았고, 4/6은 가장 좋은 순간이라 했다 — B 둘은 완벽한 팝이 가장 좋았다).

## 7. 한계

- AI는 사람이 아니다. 즐거움·재방문은 대리 판단이고, 평가자는 게임을 만든 쪽이다.
- AI의 손은 느리다(초당 0.07–0.36 입력). 시간 기준(60초 업그레이드 등)은 사람에 대한 증거가 아니다.
- 화면은 명령의 순간에만 본다: 누르는 동안의 움직임, 짧은 효과, 소리는 플레이어에게 없었다. 녹화(`screen.mp4`)에는 있다.
- 실험당 1차 1명 + 2차 1명. 같은 조건의 반복이며, 다른 조건(가로 화면·느린 기기·소리 끔)은 하지 않았다.
- 블라인드는 지시 + 사후 감사이고 샌드박스가 아니다(위 감사 참고).
