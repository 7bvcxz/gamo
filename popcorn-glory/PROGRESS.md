### Step 02 — 세 실험 설계 (#99, 2026-11-03)

- A Click & Pop(탭마다 즉시 터짐) · B Perfect Pop(누르고 있다가 금색 구간에서 떼기, 실패는 너그럽고 0은 없음) ·
  C Pop Explosion(8탭으로 채우면 연쇄 폭발, 그리는 조각 ≤ 400). 기계 하나·돈 하나·주 행동 하나·업그레이드 버튼 하나.
- 경제는 가설이다. 손 모델로 고른 값: A 탭당 팝 `[1,2,3,4,6,8,11,…]`·가격 `30×1.7^L`, B 한 판 `5×1.6^L`·가격 `25×1.9^L`,
  C 폭발 `10×2.2^L`·가격 `30×2.6^L`. 꾸준한 플레이어 기준 첫 업그레이드 9–14초, 3분에 Lv8–9.
- 모델이 잡은 것: 첫 가격 곡선은 A가 3분에 12단계를 넘겼다(너무 쌈). 반올림한 지수 표는 A의 1단계 업그레이드가 탭당 팝을
  바꾸지 않았다(1→1) — 눈에 보이는 변화가 없는 업그레이드라 명시적 표로 바꿨다.

### Step 03 — Godot 토대와 웹 검사 (#100, 2026-11-03)

- 프로젝트: `config/name` `Popcorn Glory`, 세로 720×1280 `expand`(넓은 창은 1.3배), 터치 → 마우스 에뮬레이션이고 누름은
  마우스 이벤트만 센다(손가락 하나 = 한 번). 버스는 `default_bus_layout.tres`에 선언. 오토로드 없음, 저장 없음.
- 규칙 코어(`core/rules.gd`): 정수 ms·정수 돈, `execute`는 `{ok, reason 키}`, 이벤트로 알린다. 스텁: 누름 = `pops[L]`개 = $`pops[L]`.
- 틀: 뒤로·다시 시작(아이콘), 돈(동전+숫자), 업그레이드 버튼(다음 기계 실루엣 + 가격, 돈만큼 차오름), 8초 무입력 고리·20초 손가락,
  3:00이 지나면 시계 알약(개발 모드는 항상).
- 테스트: 헤드리스 34(단위 23·통합 10 + 도형 1), 브라우저 E2E 4 시나리오 × 3 화면 = 12.
- 그림을 눈으로 보고 잡은 것: 그림 함수가 그림자 뒤에 `draw_set_transform`을 초기화해 기계가 화면 구석에 그려졌다(테스트 전부 통과
  상태였다), 반투명 둥근 사각형의 겹침이 모서리에 원으로 보였다, 최고 단계 기계가 화면을 넘쳤다.
- 브라우저가 잡은 것: 몇 픽셀 높이의 채움에서 둥근 사각형이 퇴화해 "Invalid polygon data"(데스크톱 콘솔). 헤드리스로는 안 보인다.

### Step 04 — 세 실험 (#101, 2026-11-03)

- A Click & Pop: 누름마다 `pops[L]`. 빠른 연타는 그림만 키운다(돈은 같다).
- B Perfect Pop: 누름 → 열, 뗌 → 덜 익음 ×0.3 / 완벽 ×2 / 조금 탐 ×0.6, 끝까지 누르면 저절로 탐 ×0.25(최소 $1). 식는 0.4초 동안의 누름은
  거절. 금색은 1.4초부터 `450 + 50L`ms(최대 800). 고리는 기계 **앞**에 그린다(뒤에 두었더니 높은 단계의 넓은 기계가 금색을 가렸다).
- C Pop Explosion: 8탭 = 폭발 `burst[L]`, 폭발 중의 탭은 다음 통, 끝나는 순간 가득 차 있으면 바로 다음 폭발. 그리는 조각은 폭발당 300, 풀 400.
- 실제 규칙 스크립트 플레이어(`tools/selftest.gd`): A·C는 손 모델과 같은 값, B는 달라서(숙련이 3분 안에 표 끝에 닿음) B만 잠정 보정
  (14단계, `30×1.8^L`). '3:00에 다음까지 ≤ 20초'는 A만 만족 — Step 06의 일.
- 렌더: 기계가 숨쉬기 때문에 매 프레임 통째로 다시 그려졌고 최고 단계에서 그리기 호출이 48→95로 늘었다. 기계를 자기 노드로 떼어
  단계가 바뀔 때만 다시 그리고 숨쉬기·눌림은 scale로 한다(`test_the_machine_is_redrawn_only_when_its_look_changes`).
- 테스트: 헤드리스 50, 브라우저 기능 E2E(세 화면), 실제 3분 플레이 × 3 실험 × 2 화면(`play180.spec.mjs`).

### Step 08 — 블라인드 AI 플레이테스트 (#110, 2026-11-03)

- 방식: 실험마다 **새 에이전트** 하나가 공개 URL의 실제 Chromium(400×860, DPR 1.5, 터치, 소리 켬)을 화면 명령 7개로만 3분 플레이.
  컨트롤러가 명령·메모·스크린샷·게임 기록·5초 상태·녹화를 남긴다(`tools/blind/`). 블라인드는 지시로 지키고, 플레이어 기록의 모든
  도구 호출을 `tools/blind/audit.py`로 감사했다(6명 모두 화면 밖 호출 0, 가짜 기록 대조군은 걸림).
- 1차(0.7.0) → UI 장애 넷 수정 → 2차(0.8.0, 새 에이전트 셋). 고친 것: 3:00 시계는 `?dev=1`·`?trial=1`에서만(3/3이 마감으로 읽음),
  B의 대기 힌트는 '누르고 있는 손가락 + 금색까지 도는 열의 유령', B의 뗀 눈금·연기 3초, A는 누를 때마다 최소 4조각.
- 결과(AI 대리, 두 실행 평균 Q1–Q4): A 5·4·3.5·2.5, B 2.5·4.5·4·4, C 5·4·4·3. 6/6이 글 없는 업그레이드 카드와 바뀌는 기계를 좋다고 함.
  A·C 4/4가 업그레이드 사이의 반복을 말함. B는 발견이 가장 어렵다(1차 우연 2:13, 2차 1:46).
- 한계: AI의 손이 느려(초당 0.07–0.36 입력) 60초 업그레이드 같은 시간 기준은 사람의 증거가 아니다. 소리·누르는 동안의 움직임은 플레이어에게 없었다.
- 검증: 헤드리스 73/73, 로컬 전체 85/0/10, 공개 0.8.0에서 2차 세 세션 실행(페이지 오류 0).
