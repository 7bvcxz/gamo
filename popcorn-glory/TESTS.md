# Popcorn & Glory — 테스트 목록

테스트를 추가하면 여기에 한 줄을 넣는다. 각 줄은 **무엇을 막는가**다.

## 한 줄로

```bash
popcorn-glory/tools/test_all.sh                 # 헤드리스 → 배포 → 브라우저(모든 스펙) → 보고서
popcorn-glory/tools/test_all.sh --focused       # 빠른 묶음: 영역마다 하나(tools/specs.mjs FOCUSED)
popcorn-glory/tools/test_all.sh --slow          # + 실제 시간 세션(play180, play_stand, sessions22)
popcorn-glory/tools/test_all.sh --perf          # + 벤치마크(perf46, render_probe)
popcorn-glory/tools/test_all.sh --only=save45,ui44   # 이 스펙만
popcorn-glory/tools/test_all.sh --public        # 공개 URL을 대상으로(배포 없음)
popcorn-glory/tools/test_all.sh --no-headless   # 헤드리스 단계를 건너뜀(SKIPPED로 남음)
```

**Step 46부터 브라우저 스펙 목록은 손으로 적지 않는다.** `tools/specs.mjs`가 `tests/e2e/specs/`에서 만든다. 전체 실행에서 빠지는 스펙은 `ON_DEMAND`에 이유와 함께 적고, 보고서의 `run_info.json`·`report.md`가 실행한 스펙, 빠진 스펙과 그 이유, 시작·끝의 부하와 남은 메모리를 남긴다. 손으로 적던 목록은 Step 43 이후의 스펙(ui44, save45 …)을 조용히 빼먹고 있었다.

보고서는 `tests/results/step07/report.md`·`report.json`이다(`POPCORN_REPORT_DIR`로 다른 폴더에). 공개 URL 대상 실행만 실패한 검사를 한 번 재시도하고, 재시도로 통과하면 `PASSED (on retry)`와 첫 시도의 오류를 남긴다(K12에서는 다른 세션의 도커 인터페이스 변동으로 `net::ERR_NETWORK_CHANGED`가 난다). 검사마다 PASSED, FAILED, SKIPPED(이유와 함께) 중 하나이고, git SHA, 빌드, 실패한 검사의 오류가 함께 남는다. 돌릴 수 없었던 검사는 PASSED가 아니라 SKIPPED다.

메모리가 5GB 미만이면 브라우저 단계를 기다린다. 10분이 지나도 그대로면 SKIPPED(memory)로 남긴다. K12는 메모리 고갈로 네트워크가 끊긴 적이 있다.

CI(`.github/workflows/popcorn-glory.yml`)는 `popcorn-glory/**`가 바뀔 때와 **매주 월요일 03:17 UTC**에 돌고, 헤드리스 검사(`tools/check.sh`)만 한다. 로그는 아티팩트(14일)로 남는다. 다른 게임에는 아무 부담이 없다. `tools/test.sh`의 전체 시간 제한은 1800초다(Step 46: 600초였는데 스위트가 이 기계에서 540–560초가 되자 CI의 느린 러너에서 Step 43부터 매번 "Killed"(137)로 빨갛게 끝났다 — 시험 실패가 아니라 하네스 한도였다).

## 기준 환경 (임계값의 근거)

- **기계**: K12(GMKtec NucBox K12, Ubuntu 24.04, 16코어, RAM 56.7GiB). 다른 세션들과 함께 쓰므로 부하 평균이 20–67, 스왑이 꽉 찬 때가 있다.
- **브라우저**: Playwright 1.64.1 + Chromium 156 headless shell. GPU가 없어 소프트웨어로 렌더한다.
- **FPS**: 같은 정지 화면이 30분 사이에 60과 39로 측정됐다. 그래서 FPS는 기록만 하고, 10 미만으로 무너질 때만 실패로 센다. 성능 문은 결정적인 값으로 세운다: 그리기 호출 ≤ 200(측정 최대 139), 조각 ≤ 400.
- **로딩**: 측정값 2.3–4.2초(엔진 wasm이 대부분)다. 문은 20초로 넉넉하게 둔다. 부하가 큰 기계에서 공개 URL을 연다는 전제다.
- **JS 힙**: 1분 플레이 동안 30MB 미만 증가.

## 시뮬레이션 (`tools/selftest.gd`, `tools/sim/runner.gd`)

자동 시뮬레이션이고 사람의 플레이가 아니다. `runner.gd`는 21개 행동의 불변식(돈 ≥ 0, 돈 = 번 돈 − 쓴 돈, 살 수 있을 때만 구매)을 매 사건마다 검사하고, `--replay`로 브라우저 실행의 입력을 재생해 게임과 같은 결과인지 확인한다.

`tools/sim/stand.gd`(Step 10)는 가게의 진짜 규칙으로 열세 플레이어를 20분 돌린다(숙련·중간·초보 × 양념, 흔들지 않음, 손을 거의 쓰지 않음, 자동화를 사지 않음, 자동화를 먼저 삼). 해금·구매 시각, 3분 뒤 가장 긴 '살 것 없음', 조수의 몫, 사다리 칸마다 회수 시간을 표로 내고 같은 불변식을 10ms마다 본다. 결과: `tests/results/step10/stand_sim.md`.
```
godot --headless --path popcorn-glory --script res://tools/sim/stand.gd -- --out res://tests/results/step10
```
