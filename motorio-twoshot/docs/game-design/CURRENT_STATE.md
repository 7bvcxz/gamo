# CURRENT_STATE — 기존 구현과 이 비전의 대조

`../../VISION.md`가 단일 원본이다. 이 문서는 저장소에 **이미 있는 것**을 비전과 맞대어
보고, 무엇을 가져오고 무엇을 버리고 무엇을 새로 만들지를 정한다.

분석 대상: `../motorio-oneshot` (v0.20.x, GDScript 9,284줄, 테스트 30종)과
`../motorio` (v0.4.19, 1세대). 이 문서에서 "현재 구현"은 별말이 없으면
`motorio-oneshot`을 뜻한다 — Grim, 체온, 고양이, 벨트가 전부 거기 있다.

**결론을 먼저 적는다.** `motorio-oneshot`은 비전의 Level 2까지를 이미 상당 부분
구현했고, 그중 상당수는 비전이 요구하는 것보다 잘 되어 있다. 다시 만들어야 하는 것은
많지 않다. 다만 **고양이를 얻는 경로 하나가 Pillar 3과 정면으로 충돌**하며,
그것이 이 대조에서 가장 중요한 발견이다.

---

## 1. 현재 이미 잘 구현되어 있는 것

그대로 가져올 가치가 있는 것들. 되도록 다시 만들지 않는다.

| 시스템 | 현재 상태 | 비전과의 관계 |
|---|---|---|
| **체온** | 시작 30, 반경 밖 13/초 감소, 밤 7.5/초 추가 감소, 쓰러짐 유예 5초 | Level 0의 핵심 압력 그대로. 시작값 30까지 비전과 일치 |
| **온기 = 공간** | 기본 반경 7칸 + 열당 0.022칸, 최대 22칸 | **Pillar 1의 교과서적 구현.** 열이 숫자가 아니라 원이다 |
| **추위 = 벽이 아님** | 반경 밖 진입 자유, 체온만 깎임. Hard Gate 없음 | **Pillar 2 이미 충족** |
| **낮/밤** | 하루 180초, 황혼 95초, 밤 50초. Shelter 취침, 야간 카메라 줌 | Level 0의 밤 설계 그대로. Hard Lock 없음 |
| **첫 자동화 = 병렬성** | 손 채굴 10초 = 채굴기 10초. **의도적으로 같음** | `CORE_LOOP.md` §7 그 자체. 코드 주석에 이유까지 적혀 있다 |
| **해금 = 사건** | 첫 수정 → 채굴기·교환기 / 첫 구리 → 벨트·발전기·분배기 | `VERTICAL_SLICE.md` §4의 "시간이 아니라 사건" 그대로 |
| **거리 = 난이도** | 수정 4~9.5칸, 구리 11~17칸 링 배치 | 반경 확장이 새 자원으로 보상되는 구조 |
| **벨트·분배기·전력** | 3등급 벨트(약 45.9개/분), 분배기, 발전기 1.0 : 채굴기 0.5 | Level 2의 물류·전력 뼈대 완성 |
| **고양이 상태 기계** | 대기/이동/작업/식사/귀가/수면 + 운반 2종, 허기, 야간 귀가 | 노동력으로서의 고양이는 이미 충분 |
| **Grim 자산** | 128px 8프레임, 발 기준점 정규화, 남/동/북 + 서쪽 반전 | 재생산 불필요 |
| **인프라** | 저장, 설정(UI/게임 배율), 터치, 음악/효과음, 한글 폰트 서브셋(19MB→90KB), 헤드리스 시나리오 트레이서 | 새 프로젝트가 처음부터 다시 풀 필요 없는 문제들 |

**특히 언급할 것**: `tools/trace_scenario.gd`는 헤드리스로 3일치를 돌려 30초마다
고양이 상태와 채굴기 정지를 찍는다. `GOAL.md`의 "30분 이내"를 감이 아니라 측정으로
증명하려면 이런 도구가 필요하고, 이미 하나 있다.

## 2. 현재 방향과 맞지만 개선이 필요한 것

버릴 이유는 없으나 비전 기준으로 손봐야 하는 것들.

| 항목 | 현재 | 필요한 변화 | 이유 |
|---|---|---|---|
| 기지 설치 | 월드 생성 시 `core_cell`에 자동 배치 | 플레이어가 **고른 자리**에 설치 | 첫 결정이 "내 세계의 중심"이어야 뒤의 확장에 의미가 생긴다 (`VERTICAL_SLICE.md` 구간 1) |
| 초기 연료 | 수정 → 교환기 → 에너지결정 (제작물) | 직접 캐는 열에너지 광물(Heatstone) 우선 검토 | 첫 10분에 가르칠 것이 하나 줄어든다. 단 `[질문]` — 실측으로 정한다 |
| 고양이 배치 | 채굴기 위에 올림 | 광맥 위에 직접 올림도 가능해야 | Level 1이 Level 2(기계)보다 먼저 온다. 기계 없이 첫 자동화가 성립해야 한다 |
| Shelter | 코어 기준 고정 오프셋 | 줍고 설치하는 물건 | 구간 1의 해금 사슬 |
| 탐험의 보상 | 자원 링뿐 | 자원이 아닌 것(마을·파편·유적)을 섞기 | `CORE_LOOP.md` §9의 "탐험이 자원 수집이 됨" 위험 |
| 진행 범위 | Level 1~3 상당 | Level 3 이후의 뼈대 | 지금은 필요 없다. P2 이후 |

## 3. 게임 비전과 충돌하는 것

**되돌리거나 다시 설계해야 하는 것.** 완성도와 무관하다.

### 충돌 1 — 고양이 뽑기 (가장 중요) `[확정: 충돌]`

현재 고양이를 얻는 두 경로:

```
상자 3개를 주움 → 고양이 1마리
슬롯머신 버튼 → 1회/3회/10회 뽑기 → 등급별 고양이 (SSR은 돼지)
```

비전이 요구하는 경로:

```
얼어붙은 고양이 발견 → 안아서 운반 → Heat로 해동 → 눈을 뜬다 → "먀?"
```

**왜 충돌인가.** Pillar 3은 "고양이는 구조 대상이지 유닛이 아니다"이고, 이 게임이
검증하려는 핵심 재미 1번이 "발견하고 구한 뒤 일을 시키는 재미"다.
슬롯머신은 **발견과 구조라는 동사를 통째로 삭제하고 버튼 하나로 대체한다.**
그 순간 고양이가 왜 고양이여야 하는지가 사라지고, 남는 것은 "귀여운 스킨을 씌운
자동화 게임"이다 — VISION §3이 명시적으로 피하려는 것.

10연차가 재미없다는 말이 아니다. **다른 게임의 재미**라는 말이다.

권고:
- `motorio-twoshot`에서는 뽑기를 이식하지 않는다.
- `motorio-oneshot`의 뽑기를 지우라는 뜻은 아니다. 그 게임은 별개의 실험이고,
  사용자의 기존 작업을 되돌리지 않는다는 것이 이 저장소의 규칙이다.

`[질문]` 상자 3개 → 고양이 경로는 남길 만한가? "얼음에서 구한다"와 공존하려면
상자가 무엇인지에 대한 설명이 필요하다. 지금은 이식하지 않는 쪽을 권한다.

### 충돌 2 — 시작부터 존재하는 기지 `[초안: 충돌]`

현재는 세계 생성 시 코어가 이미 있다. 비전의 Level 0은 **불시착한 사람이 기지를
세우는 것**에서 시작한다. 기지가 처음부터 있으면 "나 얼어 죽겠다"가 아니라
"여기가 내 집이다"에서 시작하게 되고, 첫 3분이 통째로 사라진다.

### 충돌 아님으로 판정한 것

- **고양이 허기** — 벌이 아니라 압력이고, 굶어도 죽지 않는다. 비전과 맞다.
- **하루 180초** — 짧아 보이지만 하루가 끝나는 게임이 아니라 반복되는 리듬이므로
  한 세션에 여러 번 느끼는 편이 맞다.
- **SSR 돼지** — 톤(귀엽고 황당함)에는 오히려 맞다. 문제는 돼지가 아니라 슬롯머신이다.

## 5. 삭제하거나 단순화할 후보

`motorio-twoshot`으로 **이식하지 않을** 후보다. 기존 게임에서 지우자는 뜻이 아니다.

| 대상 | 판단 | 이유 |
|---|---|---|
| 슬롯머신 뽑기 | **이식 안 함** | 충돌 1 |
| 상자 3개 → 고양이 | 이식 안 함 `[질문]` | 구조와 경로가 겹친다 |
| 고양이 등급(O/SSR) | 보류 | 등급은 "구조한 개체"보다 "뽑은 상품"에 어울린다. 개체차가 필요하면 등급이 아니라 성격/특기로 |
| 교환기(수정→에너지) | 재검토 | Heatstone 직접 채굴로 가면 초반에서 빠진다. 중반 가공 체인으로 옮길 수는 있다 |
| 1세대 `motorio`의 시스템 | 참고만 | 기지 7단계, 미니맵, 연구소 등은 별개 설계다. 코드가 아니라 교훈만 가져온다 |
| 미니맵 | 신중히 | 1세대에 있고 One Shot에는 걸어본 곳만 남는 안개 지도가 있다. 후자가 이 게임의 탐험과 맞다 |

## 6. 우선순위

### P0 — Vertical Slice에 필수

`GOAL.md`의 완료 조건과 1:1로 대응한다. 이것이 다음에 할 일 전부다.

1. 프로젝트 뼈대 (`project.godot`, Web export preset) — 아직 Godot 프로젝트가 아니다
2. 체온 게이지와 반경 밖 감소
3. 불시착 → 긴급기지 설치 → Heat Zone 생성
4. Heatstone 채굴 → 기지 공급 → **반경이 눈에 보이게 확장**
5. 낮/밤 사이클, 밤 감소 가속, Shelter 취침 (Hard Lock 없음)
6. **얼어붙은 고양이 발견 → 운반 → 해동 연출("먀?")** ★
7. 고양이를 광맥 위에 놓으면 채굴 + 운반 시작
8. 구리 발견 → Conveyor 제작 → 자동 라인 1개 ★
9. 30분 도달을 **측정**하는 헤드리스 시나리오 도구
10. 헤드리스 에러 0, HTML5 export, 모바일 터치

`★`는 검증 질문이 직접 겨냥하는 두 순간이다. 나머지가 조금 거칠어도 이 둘은 거칠면 안 된다.

### P1 — Early Game 완성

- Torch 충전과 탐험 제한 시간의 실제 튜닝
- 고양이 2~3마리로 늘었을 때의 배치·허기 밸런스
- 분배기, 벨트 등급
- 첫 밤의 선택(취침 / 강행)이 실제로 갈리는 밸런스
- 저장/불러오기
- 튜토리얼을 문장이 아니라 상황으로 가르치는지 실측 검증

### P2 — Mid Game

- High Energy Torch와 눈안개 지역
- Crystal(기술 자원)과 이름 정리
- Heat Relay / Pipe — 열을 멀리 보내기
- 전초기지와 장거리 물류
- Cat Village 1개와 해동 연출
- Lv4~6 세부 설계 (`PROGRESSION.md`의 `[질문]` 해소 후)

### P3 — Late Game / Story

- Spaceship Fragment 배치와 수집
- 냥파편 발견·분석·기술 트리
- Lore 전달 방식 확정 및 배치
- 우주선 복원
- Normal Ending
- True Ending — 복수의 자동화

### P4 — Post-game / DLC

- 펭귄 행성
- 새 환경·자원·펭귄 시스템

**지금 구현하지 않는다.**
