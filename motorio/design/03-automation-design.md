# Motorio — 자동화 디자인

> 블록, 생산 체인, 작업자, 그리고 "규모를 키울 수 있는가"를 정한다.
> 정체성은 `01-identity.md`, 월드와 수치는 `02-level-design.md`.
> 상태 표기: **[확정]** 구현·검증됨 / **[초안]** 제안 / **[질문]** 결정 필요

---

## 1. 블록 특성 체계

**[확정]** 모든 배치물은 네 가지 특성 중 하나를 가진다. 새 블록을 만들 때 반드시 하나를 고른다.

| 특성 | 겹침 규칙 | 해당 블록 |
|---|---|---|
| `Solid` | 주인공·다른 Solid와 겹칠 수 없음 | 상자, 고양이, 기둥, 박스 생성기, 제련소, 설비, 연구소 |
| `Machine` | 주인공만 막고 블록과는 겹침 | (현재 없음, 예약) |
| `TransportFloor` | 모든 것이 위에 겹침, 운송 효과만 | 컨베이어, 분배기, 다리 |
| `Fixed` | 회수 불가, 겹침 불가 | 미네랄 원석, 단계 원석, 물 타일 |

## 2. 현재 생산 체인

**[확정]**

```
미네랄 원석 ──(광부 고양이)──> 미네랄 자원 ──┬──> 기지 납품 (미네랄 수치)
                                            │
                                            ├──(박스 생성기: 미네랄 3)──> 상자 ──> 기지 납품
                                            │
                                            └──(제련소: 미네랄 2 + 석탄 1, 2초)──> 금속판 ──> 기지 납품
석탄 원석 ──(배부른 광부)──> 석탄 ─────────────┘
```

**[확정]** 금속판은 기지 7단계 업그레이드에 물고기와 함께 필요하다. 체인이 목적 없이
존재하지 않도록, 모든 산출물은 반드시 어딘가에서 소비되어야 한다.

> **[질문]** 체인을 몇 단계까지 깊게 할지. `01-identity.md`에서 "Factorio보다 얕게"로
> 잡았으므로 2~3단계가 상한이라고 본다. 다음 후보:
>
> - 금속판 + 수정 → **부품** → 고급 기계 제작 재료
> - 석유 → **연료** → 기계 가동 속도 상승
> - 우라늄 → **동력 코어** → 최종 목표물의 재료

## 3. 작업자(고양이) 시스템

**[확정]** 고양이는 방향을 가진 `Solid` 블록이며, 3초마다 앞칸에 작업한다.

| 역할 | 하는 일 | 필요 설비 |
|---|---|---|
| 광부 | 앞칸 원석을 캐서 뒤로 자원 배출 | 없음 |
| 압력 | 석유 채굴 | 없음 |
| 전기 | 석탄으로 전력 생산 | 발전기 |
| 낚시 | 물고기 생산 | 낚시장 |
| 서빙 | 주변 작업자에게 물고기 배급 | 없음 |

**[확정]** 허기가 낮으면 작업 주기가 느려진다(35 미만 1.8배, 0이면 3배). 설비 개수와
고양이 개수 중 **작은 쪽**만큼만 생산된다 — 고양이만 늘려도 소용없다.

> **[질문]** 지금 고양이를 늘리면 생산이 **선형**으로만 는다. 설계를 잘해서 배로 늘어나는
> 지점이 없다. 이것이 "공장을 키우는 재미"가 약한 근본 원인이다. 후보:
>
> - (a) **인접 보너스** — 같은 종류 기계가 붙어 있으면 속도 증가
> - (b) **가동 속도 업그레이드** — 연료/전력을 대면 기계가 빨라짐
> - (c) **일괄 처리** — 입력을 많이 모을수록 배치당 효율 증가

## 4. 규모 확장 — 2D에서 가능한가

**[확정] 가능하다. 차원은 제약이 아니다.** Factorio 자체가 2D 탑다운이며 수만 엔티티를
처리한다. 3D 전환은 정점·셰이더·드로우콜 비용만 더하며, 모바일 WebGL에서는 명백히 불리하다.

**[확정] 진짜 제약은 엔티티당 매 프레임 비용이다.** 과거에는 화면 밖 100칸 떨어진
컨베이어도 매 프레임 그리기 명령을 새로 만들고 있었다. 지금은 `WorldView`가 카메라
사각형을 프레임당 한 번 게시하고, 각 기계가 그리기 전에 화면 안인지 확인한다.
**시뮬레이션은 계속 돌고 렌더 갱신만 건너뛴다.**

**[초안] 남은 확장 병목** — 규모를 더 키울 때 손볼 순서:

1. **물리 기반 아이템 운반** — 상자와 자원이 전부 `RigidBody2D`다. Factorio는 벨트 위
   아이템을 물리로 굴리지 않는다. 수백 개를 넘어가면 여기가 먼저 무너진다.
2. **조작 대역폭** — 5칸 인벤토리로 블록을 하나씩 놓아야 한다. 모바일에서 큰 공장을
   짓는 것이 물리적으로 지친다. 연속 설치나 인벤토리 확장이 필요하다.
3. **개별 `_draw()`** — 블록마다 직접 그린다. 수천 개 규모에서는 배칭이나 타일맵이 필요하다.

> **[질문]** 목표 규모를 정해야 설계가 정해진다. 화면 가득한 공장(수백 개)이 목표인지,
> 화면 여러 개 분량(수천 개)이 목표인지에 따라 1번 리팩터링의 필요 시점이 달라진다.

## 5. 새 블록을 추가할 때 (구현 체크리스트)

**[확정]** 블록 하나를 추가하면 아래를 모두 건드려야 한다. 하나라도 빠지면 설치는 되는데
저장이 안 되거나 아이콘이 없는 식으로 부분적으로 깨진다.

1. 블록 스크립트의 `_ready()` 그룹 등록 (특성 + 기능 그룹)
2. `.tscn`의 충돌 레이어/마스크
3. `Main._pick_up_front_block()` — Z 회수
4. `Main._place_selected_block()` — X 설치
5. `Main._create_placement_preview()` — 반투명 미리보기
6. `Main._can_place_item_at()` — 1×1이 아니면 크기 처리
7. `Main._serialize_world_object()` — 저장
8. `Main._create_saved_world_object()` — 복원
9. `InventoryUI._draw()` — 인벤토리 아이콘
10. 제작 가능하면 레시피 표(라벨·해금 단계·비용·생성 함수)
11. 매 프레임 다시 그린다면 `WorldView.is_on_screen()` 검사

## 6. 열린 과제

- **[질문]** 처리량이 배로 늘어나는 지점을 어떻게 만들지 (3절).
- **[질문]** 체인의 최대 깊이와 다음 단계 산출물 (2절).
- **[질문]** 목표 규모와 물리 운반 리팩터링 시점 (4절).
- **[초안]** 지금은 기계가 서로 무관하다. 인접성이나 배치가 의미를 갖게 되면
  "설계하는 재미"가 생긴다 — 이것이 자동화 게임의 핵심이라고 본다.
