# Motorio — 테스트 목록

무엇이 어떤 결함을 막고 있는지, 그리고 어떻게 돌리는지. 사용자가 이름을 부르면
해당 항목만 수행한다.

전부 돌리기:

```
cd motorio
for t in tests/test_*.gd; do godot --headless --path . --script res://$t; done
```

하나만 돌리기:

```
godot --headless --path . --script res://tests/test_touch.gd
```

> **종료 코드로 판단하지 않는다.** Godot headless는 스크립트 오류에도 0을 반환할 수 있다.
> 출력의 `PASS`/`FAIL`과 `SCRIPT ERROR`를 함께 본다. 결과 없이 멈추면 타임아웃을 늘리지
> 말고 `timeout -s KILL`로 로그를 파일에 받아 마지막 `SCRIPT ERROR`부터 읽는다.

## 자동 테스트 (headless, 61개)

### 규칙과 진행

| 테스트 | 지키는 것 |
|---|---|
| `test_machines` | **기계 레지스트리.** 표가 성한가(번호·key 중복, group/production 유효값, 핫바 자리 충돌, 비용·해금이 실재하는 자원인가, 전력 음수), 검증기가 **일부러 망가뜨린 표**를 잡는가. 모든 기계가 번호로도 key 로도 조회되는가. 그리고 **아홉 개 목록이 표 하나로 합쳐지면서 값이 하나도 안 움직였는가** — 이름·약칭·설명·비용·해금·핫바 순서·밟기·방향·색·전력을 마이그레이션 전 값으로 손수 고정해 둔다. 마지막으로 세 레지스트리가 서로 어긋나지 않는가(비용이 실재 자원을, 레시피가 레시피를 도는 기계를), 그리고 지을 수 있는 기계를 전부 세워 세이브를 왕복하는가 |
| `test_recipes` | **레시피 레지스트리와 공용 생산 tick.** 표는 아직 비어 있고, 그것이 맞는 답인지부터 확인한다 — 채굴기는 세계에서 캐고 발전기는 전력을 내므로 둘 다 입력→출력 쌍이 아니다. 검증기는 **일부러 망가뜨린 데이터**를 먹인다(번호·key 중복, 없는 자원, 수량 0/음수, 시간 0, 없는 기계, 항목 누락) — 맞는 표만 본 검증기는 아무도 돌아가는 걸 본 적 없는 검증기다. **조립기가 전동기를 요구하고 전동기는 조립기만 만드는 매듭**을 의존성 검사가 잡는가. 그리고 공용 tick: 재료가 모자라면 안 돌고, 끝나야 먹고, 앞이 막히면 **일한 것을 들고 기다리며 다음 주기를 시작하지 않고**, 길이 열리면 내보낸다. 들고 있던 산출이 세이브를 왕복하는가 |
| `test_items` | **아이템 레지스트리.** 번호·key 중복 금지, `kind` 가 셋 중 하나인가, counter/ore_tier 자리를 두 행이 다투지 않는가. **은퇴한 0·3번이 표에 남아 있고 여전히 crystal·stone 인가** — 세이브가 자원을 번호로 적으므로 은퇴 번호를 새 자원에 주면 어디서도 실패하지 않고 옛 회차의 열석이 조용히 돌이 된다. 모든 항목이 번호로도 key 로도 조회되는가, 없는 번호가 크래시 대신 빈 행을 답하는가. 그리고 **리팩터가 플레이어에게 보이지 않았는가** — 표시 이름·약칭·색 다섯과 자원 패널 순서와 광맥 사다리 순서를 손으로 고정해 둔다. 마지막으로 시트를 선언한 자원과 `GroundLayer` 가 그리는 자원이 같은가, 은퇴 번호까지 포함해 세이브를 왕복하는가 |
| `test_sim` | 아이템 흐름, 기계 tick, 자원 집계. 그리고 **발전기 연료를 이름 부르는 모든 자리가 같은 재료를 말하는가** — 여섯 곳이 있었고 다섯만 옮겼을 때 발전기는 연료를 태우면서 전력을 0으로 냈다. 다섯은 `Defs.GENERATOR_FUEL`을 읽어 어긋날 수 없고, 건설 목록의 산문 한 줄은 파생될 수 없으므로 여기서 대조한다 |
| `test_progression` | 해금 순서, 광맥 순도, 온기 반경. **구리는 운송 줄만 열고 발전기는 에너지 코어까지 와야 열리는가**, 그리고 둘 중 무엇이 마지막에 오든 같은 답이 나오는가. 그리고 **사다리의 칸값이 표에 적힌 그대로인가** — `stones` 열은 누적치라 실제로 내는 값은 두 행의 차이이고, 그 차이가 3·6·6·12이던 시절에는 다음 광맥까지의 거리가 늘어나는 구간에서 사다리가 오히려 싸졌다 |
| `test_flow` | 벨트·분배기·교환기를 지나는 자원의 경로. 그리고 **Z는 아무리 오래 눌러도 방향을 돌리지 않고 R만 돌리는가** — 실제 프레임을 1초 돌려서 묻는다. 예전에는 홀드를 재던 함수 하나를 불러서 물었는데, 그 함수는 비어 있었고 나중에 아예 사라졌다: 한 함수만 부르는 검사는 그 함수가 조용하다는 것만 증명한다 |
| `test_belt` | 벨트 속도와 등급. **셋업 헬퍼가 발전기를 켜두면 전력 없는 경로가 한 번도 실행되지 않는다** |
| `test_belt_art` | 벨트가 이웃을 보고 직선/코너를 고르는 규칙과 회전 방향, 타일 크기와 이음매. 그리는 모양이 저장된 값이 아니라 이웃에서 나오므로, 이웃이 바뀔 때 갱신을 잊을 자리가 없다 |
| `test_build` | 설치·회수 규칙, 광맥 위 제약 |
| `test_meter` | 처리량 측정 창과 설계 수치. 발전기의 입력 줄이 실제 연료를 말하는가 |
| `test_workers` | 고양이 배치, 허기, 작업 속도. **떨어진 자원은 가장 가까운 노는 고양이 하나만 맡는가**, 노는 고양이가 실제로 어슬렁거리며 숙소 근처를 벗어나지 않는가 **사료 상자는 만들어서 들고 가 놓는가**, 그리고 하나뿐인가 — 메뉴에서 바로 세워지던 유일한 건물이었다. |
| `test_opening` | 추락 지점의 첫 13분. **기지를 바라보고 Z로 연료가 들어가는가**(손으로 캔 열석은 여기 말고 불에 닿을 길이 없었다), 자재는 남는가, 세 번째 임무가 온기를 정확히 9칸으로 만들고 **그 순간 얼어붙은 고양이가 온기 안에 들어오는가**. 기지도 거처도 없는 세계로 시작하는가, **오프닝 동안 하루가 멈추는가**, 상자에서 두 번 나오고 세 번째는 없는가, 기지가 추락 지점 2칸 안에만 놓이고 **놓는 순간 세계의 중심이 그리로 옮겨가는가**(옮겨간 좌표가 저장되지 않으면 불러온 세계의 안개·숙소·광맥 고리가 화면의 불과 다른 자리에 온다), 체온 0이 오프닝을 끝내지 못하는가. 임무는 번호를 직접 올리지 않고 **세계를 바꾼 뒤 임무가 무엇이 됐는지 묻는다** **긴급생존키트 칸은 지나갈 수 없고**, 열었을 때 내용물이 상자 곁에 떨어지는가 — 상자 너머에 떨어뜨리면 이제 상자를 돌아가야 하고, 오프닝은 13.3초짜리다. |
| `test_frozen` | 구조 전체. 시드 200개에서 시작 반경 안에 얼어붙은 고양이가 **항상** 있는가(상자 3개가 1마리로 줄면서 한 번의 충돌이 곧 시작 불가가 된다), 안으면 정확히 절반 속도이고 달리기가 막히는가, 기지 2칸 밖에서는 녹지 않는가, 놓아둔 그 자리에서 깨어나는가. **속도는 상수를 되읽지 않고 실제로 걸려서 잰다** |
| `test_carry` | 고양이를 안고 옮기기. 들린 고양이는 시뮬레이션하지 않는다 |
| `test_walk` | **하루 동안 고양이가 순간이동하지 않는가.** 1초 간격과 매 틱 두 가지로 재고, 작업 중인 고양이가 채굴기 정중앙에 서는지 확인한다. 오른쪽에서 기지로 나르는 경로를 실제로 만들어 넣는다 |
| `test_crowd` | **고양이 8마리를 하루보다 길게 실제로 돌리며 매 틱 게이지·몸·그림자 간격을 잰다.** 걷고 먹고 귀가하는 구간이 실제로 포함됐는지도 함께 확인한다 |
| `test_gacha` | 확률표 합계, 경계값, 2만 회 분포, 코인 차감, 등급별 작업 배율, 세이브 왕복 |

### 시간과 상태

| 테스트 | 지키는 것 |
|---|---|
| `test_night` | 밤 연출의 각 구간과 상한. 하늘 덧칠 곡선(`HUD.night_wash`)이 낮 0 → 해질녘 → **밤에 계단으로 떨어지는지** — 밤은 사건이고, 0에서 서서히 오르는 두 번째 겹은 그 프레임에 아무 일도 없어 보이게 만든다. **문이 열리는 프레임에 플레이어가 그려지는지**, 그리고 하루 5분 안에 해질녘·밤이 순서대로 들어가는지 |
| `test_cutscene` | 오프닝. 표의 장 수와 `assets/cutscene`의 파일 수가 같은가(표만 고치면 없는 그림을 preload하고, 파일만 넣으면 아무도 못 본다), 새 게임에서만 재생되는가, 전체 길이, 흔들림이 결정적이고 잦아드는가, 그리고 **모든 화면비·모든 순간에 그림이 화면을 덮는가** — 16:9에서 덮는 배율은 화면과 정확히 같은 크기라 흔들림이 그대로 가장자리를 드러낸다 |
| `test_cold` | 체온 감소, 쓰러짐 유예, 구조 |

| `test_torch` | 에너지횃불. 만들기·꺼내기·타기, 그리고 **주머니 안에서는 타지 않는가** — 30초는 켜 둔 채 갈 수 있는 거리이지 만든 순간 붙는 심지가 아니다. 안개의 구멍과 바닥의 불빛이 **같은 자리·같은 크기**인가(둘 중 하나만 있으면 검은 원이거나 아무도 못 보는 불빛이다), 기지 창을 여는 것만으로는 아무것도 쓰지 않는가(횃불은 불이 태우는 그 연료로 만든다) |
| `test_fog` | 안개 세기와 미리보기 띠 |
| `test_touch_windows` | 폰이 열 수 있는 창은 폰이 쓰고 닫을 수도 있는가. **기지 창에는 히트 테스트가 아예 없었다** — 커서가 화살표 키인데 폰에는 없으므로, 열리고 나면 모든 탭이 아래 도구줄로 새고 그 아래 패드가 다시 열었다. 밖에서 보면 기지가 아무 일도 안 하는 것이다. 컷씬이 탭으로 넘어가는가(`touch_anywhere_starts`에 OPENING이 빠져 있었다), 좁은 화면에서 자원 패널과 목표 카드가 겹치지 않는가 |
| `test_debris` | **로켓잔해가 있어야 할 곳에만 있는가.** 10칸 안에 0개, **11칸에 정확히 1개**(200시드 — 이런 보장은 시드마다 달라서 한 번 돌려서는 증명되지 않는다), 12칸 밖 200칸당 1개, 시드를 건너 다섯 모양이 전부. 그리고 뜯었을 때 **광맥 최상위 등급 2~5·그 아래 5~10**(잔해가 자기 자원 목록을 갖지 않는다는 규칙도 함께), **첫 조각은 60시드 모두 에너지 코어 1개**, 그 뒤로는 4,000회를 돌려 20%/5%. 온기 밖에서는 못 뜯고 횃불을 들면 뜯는다 그리고 **구리를 캔 적이 없으면 열석만 나오는가** — 이름도 들어보지 못한 자원이 첫 잔해에서 한 상자 나오는 것은 건설 목록에서 지웠던 것과 같은 누설이다. |
| `test_crash` 참고 | 교환기가 사라지면서 `test_belt`의 생산자가 채굴기로, `test_sim`의 제련 체인이 발전기(수정조각을 태운다)로 바뀌었다. `test_progression`의 제법 절은 통째로 지웠다 — 없는 기계에 대한 주장이다 |
| `test_room` | **숙소 = 월드 격자 위의 장소.** 창문이 실내 밝기가 아니라 **바깥 시계**를 읽는가(방은 밝고 창밖은 밤이다), 그리고 정산 카드 위에 검은 천이 다시 깔리지 않는가(`room_fade_visible()` — 상태가 RESULT라는 것과 카드가 보인다는 것은 다른 주장이다).<br/> 좌표 변환이 왕복하는가, 가구와 네 벽이 `blocks_player`인가(그리고 실제로 걸어가서 막히는가), 앞칸 Z가 문이면 나가고 침대면 밤을 끝내는가, 고양이가 **깨어서 배회하되 방을 벗어나지도 가구에 올라가지도 않는가**, 눕는 순간 전부 잠드는가, 실내에서 체온이 회복되는가, 방 안에서 저장한 회차가 **밖에서** 불러와지는가 눕는 자리가 머리맡에서 **반 칸 아래**인가(두 칸짜리 침대의 위 칸 한가운데는 머리판 위다).

| `test_map` | 창(건설 목록·가챠·지도)이 열리면 주인공이 입력을 안 받는가, 얼음 잠금과 섞이지 않는가, 안개(기지는 처음부터·간 곳만·음수 좌표), 확대 범위, 탐사 기록의 저장과 옛 저장 호환 |
| `test_ground` | 눈 타일 변형의 주기성. 그리고 **그리는 쪽에도 바위가 없는가** — 시뮬레이션 쪽은 `test_stone`이 본다. 따로 보는 이유는 두 벌이기 때문이다: 충돌은 비었는데 눈밭에 바위가 그려져 있는 상태가 이 저장소가 여러 번 겪은 모양이다 |
| `test_tiles` | 지형 생성. **무작위 시드 대신 고정 시드로 부른다** |
| `test_debug` | F2 배속, F3 해금이 주는 것, F4 표준 배치, **F7이 바라보는 칸에 얼어붙은 고양이를 두는가**, F8이 벨트 넉 줄과 그 앞의 빈 칸을 만드는가 |
| `test_audio` · `test_music` | 사운드 뱅크와 악보가 로드되는가 |

## 브라우저 테스트 (사람이 부를 때)

headless는 파싱과 논리만 본다. 아래는 렌더링·입력·배포가 실제로 도는지 보는 것이고,
이름을 부르면 수행한다.

### `real test` — 표준 시나리오

**근처 수정 광맥에 채굴기 2대를 *위를 보게* 놓고, 각 채굴기에 고양이 1마리, 배치 안 한
고양이 1마리 (고양이 총 3마리).** 이 상태로 1배속으로 **3일차 밤까지** 돌린다. 1분마다
스크린샷을 찍고, 몇 분에 한 번씩 Grim에게 할 일을 시킨다.

방향이 시나리오의 일부다. 채굴기는 바라보는 칸으로 뱉으므로 나란한 광맥에 **동쪽을 보게**
놓으면 둘 다 막힌다 — 왼쪽은 오른쪽 채굴기로, 오른쪽은 세 번째 광맥으로. 위를 보게 놓으면
빈 바닥에 떨어뜨리고 유휴 고양이가 그것을 기지로 나른다. 그게 실제로 생산되는 배치다.

Grim에게 시키는 것(순환): 손 채굴 · 계기 열기 · 가챠 1연차 · 건설 목록 · 남쪽 산책 ·
화면 축소/확대. **작업 중인 고양이를 들거나 X를 누르지 않는다** — 들면 그 채굴기가 서고
X는 기계를 해체하므로, 관찰하려는 배치가 사라진다.

배치는 **`F4`(`debug_scenario`) 한 번**으로 만든다. 손으로 만들면 "왼쪽으로 1250ms 걷고
Z, 오른쪽으로 850ms 걷고 위를 보고 Z" 같은 타이밍 홀드가 열두 번이고, 한 번만 어긋나면
고양이가 채굴기가 아니라 옆 광맥 위에 선다. 그 회차는 아무것도 생산하지 않는데 그 모습이
**게임 버그와 똑같이 보인다** — 실제로 첫 파일럿이 그렇게 됐다. 검사 도구가 버그처럼
실패하는 것이 제일 나쁘다.

**`F7`(`debug_rescue`)**은 바라보는 칸에 얼어붙은 고양이를 둔다. 그 뒤는 전부 진짜다 —
절반 속도로 안고 와서 기지 2칸 안에 내려놓고 12초를 기다린다. 이 키가 있는 이유는 F4와
같다: 세계가 회차마다 새로 생성되므로 "동쪽으로 네 칸, 북쪽으로 한 칸"은 경로가 아니라
추측이고, 반 칸만 어긋나면 Z가 건설총으로 흘러가 **구조가 안 되는 게임과 똑같이 보인다.**
실제로 첫 시도에서 그렇게 됐다.

**`F8`(`debug_spill`)**은 끝이 열린 벨트 넉 줄에 열석 여섯을 실어 놓고 그 옆에 Grim을
세운다. 손으로 만들기 어려운데 **잘못 만들면 아무것도 일어나지 않고, 아무것도 일어나지
않는 것이 바로 기능이 없는 모습이다.** 온기를 최대로 올리고 체온을 채우는 것도 이 키가
한다 — 첫 판은 31% 체온으로 흰 안개 속에 세웠고 스크린샷에는 벨트도 아무것도 없었다.
열석 수치는 0으로 되돌린다. 이 키가 만드는 것이 열석이고 500에서는 여섯 개가 안 보인다.
자리는 예전에 가장 가까운 바위가 정했는데, 1.0.28에 바위가 없어져 기지에서 고정 오프셋이
됐다 — 바위가 대신하던 것이 애초에 '걸어갈 만큼 가깝고 기지 위는 아닌 자리'였다. 남는
것은 `test_debug`가 고정한다.

**`F9`(`debug_pad`)**는 터치 패드를 강제로 켠다. 패드는 `DisplayServer.is_touchscreen_available()`이 참일 때 나오는데, 터치를 흉내 낸 데스크톱 브라우저는 여전히 아니라고 답하므로 자동 검사가 패드 없는 화면을 상대하게 된다. **그리고 아무 키나 누르면 패드가 다시 숨는다** — 그것이 데스크톱 플레이어 신호이기 때문이다. 그래서 순서가 정해져 있다: 키를 먼저 전부 누르고 마지막에 F9, 그 뒤로는 터치만. CDP 터치는 캔버스에 키보드 포커스를 주지 않아서 터치 뒤의 키는 도착하지 않는다.

**`F6`(`debug_belt_loop`)**은 벨트 한 고리를 깐다 — 네 방향 직선과 네 코너, 두 회전
방향이 한 화면에 다 나온다. 벨트가 직선이냐 코너냐는 저장된 값이 아니라 **이웃**에서
나오므로, 규칙은 `test_belt_art`가 고정하고 이음매는 눈으로 본다. 깔던 자리에 광맥이
있으면 지우고 깐다 — 절반만 깔린 고리는 코너 그리기가 실패한 것과 똑같이 보인다.

확인하는 것:

- 두 채굴기가 모두 돌고 수정조각이 실제로 나오는가
- 배치된 고양이 2마리가 각자의 채굴기에 서 있는가, 작업 애니메이션이 나오는가
- 남은 1마리가 유휴 행동(바닥의 자원을 기지로 나르기)을 하는가
- 세 마리가 서로의 그림자·허기 막대를 덮지 않는가
- 허기가 떨어지면 밥통으로 가고 돌아오는가
- 밤에 셋 다 숙소로 들어가고 아침에 자기 자리로 돌아가는가
- HUD의 수정 수치가 실제 산출과 맞는가
- Grim의 행동이 배치를 방해하지 않고 각각 의도한 화면을 여는가

> **정산 카드는 `Enter`로 넘기지 않는다.** `Enter`는 `build` 액션에도 묶여 있어서 플레이
> 중에 누르면 설치를 시도한다. 카드는 화면 가운데 상자의 어두운 픽셀 비율(카드 0.96 대
> 플레이·밤·새벽 0.04 이하)로 감지하고 `Space`로 넘긴다.

### 그 밖의 브라우저 검사

| 이름 | 하는 일 |
|---|---|
| `play test` | 1배속으로 3번째 밤까지, 1분마다 스크린샷. 회차 수를 지정할 수 있다 |
| `mobile test` | 390×844 뷰포트에 실제 터치 이벤트. **`mouse.click()`은 쓰지 않는다 — 터치 레이어가 합성 마우스 이벤트를 소비한다.** 그리고 **누르고 있는 입력을 반드시 포함한다** — 아래 참고 |
| `deep test` | 랜덤 플레이가 닿지 않는 화면: 건설 목록, 계기, 가챠 10연차, 줌 양방향 한계, 설정 |
| `night test` | 밤 연출 전체를 0.7초 간격으로 촬영 |
| `zone test` | 눈밭과 숙소를 한 화면에서 비교한다. 낮에 한 번 들어가 방을 재고, 문으로 나와 밤이 될 때까지 기다린 뒤 다시 들어가 **같은 값이 나오는지** 본다. 눈과 나무 바닥은 원래 밝기가 다르므로 **밖과 안을 비교하지 않는다** — 물어야 할 것은 바깥 시계가 안까지 닿았는가이고, 그건 방의 두 값만이 답할 수 있다. 그리고 카메라에는 스무딩이 있고 숙소는 600칸 북쪽이라, **들어간 직후의 화면은 목적지가 아니라 이동 중**이다(첫 판에서 0.1을 재고 '방이 검다'고 판정했다). 10배속으로 밤을 당겼으면 들어가기 전에 1배속으로 되돌린다 |
| `perf test` | 프레임률. **같은 빌드를 3회 이상 재고 중앙값으로 판단한다** |
| `deploy test` | 배포된 URL을 열어 기대한 해시 PCK가 로드되고 캔버스에 색이 두 가지 이상 그려지는지 |

> **모바일 검사는 탭만으로 끝내지 않는다.** 채굴은 누르고 있는 동작이고, 패드가 누름만
> 보내던 시절 폰에서는 캘 수가 없었는데 **탭만 확인하는 검사로는 영원히 안 보인다.**
> `touchscreen.tap()`은 홀드를 표현할 수 없으므로 CDP로 직접 보낸다:
>
> ```js
> const cdp = await page.context().newCDPSession(page);
> const touch = (type, x, y) => cdp.send('Input.dispatchTouchEvent', {
>   type, touchPoints: type === 'touchEnd' ? [] : [{ x, y, id: 1 }] });
> await touch('touchStart', x, y); await sleep(13000); await touch('touchEnd', x, y);
> ```
>
> **"터치가 빗나갔다"와 "게임이 틀렸다"를 먼저 가른다.** 채굴 검증이 네 번 실패했는데
> 전부 조작이 엉뚱한 칸에 선 것이었고, 매번 게임이 고장난 것과 똑같이 보였다. 패드는
> 눌린 버튼을 다르게 그리므로, 두 프레임의 패드 영역을 비교해 **버튼에 불이 들어왔는지**를
> 먼저 본다. 안 들어왔으면 좌표 문제이고, 게임에 대해서는 아직 아무것도 알아낸 게 없다.

> **혼잡한 화면에서 픽셀로 재려 하지 않는다.** 고양이 여덟 마리가 있는 기지에서 게이지 아래
> 그림자를 픽셀로 찾으면 옆 고양이·드릴·기계의 어두운 부분에 붙어 편차 52px 같은 노이즈가
> 나온다. 같은 질문을 `test_crowd`가 정확히 답한다 — 화면은 그것이 이상해 *보이는지*를,
> 테스트는 그것이 실제로 어긋나는지를 본다.

브라우저 검사 준비물은 `AGENTS.md`의 "실수와 교훈"과
`~/.claude` 메모리의 browser-test-setup에 있다. 요약: Playwright를 스크래치패드에
설치하고 `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`로 띄운다.
**준비 완료 판정은 "캔버스가 있다"가 아니라 "캔버스에 색이 두 가지 이상 그려졌다"이다.**

## 이 목록에 항목을 더할 때

테스트는 **인스턴스가 아니라 결함의 종류**를 잡아야 한다. 지금까지 실제로 나온 종류:

1. 화면이 말하는 키가 다른 일을 한다 (`test_hints`)
2. 터치가 키보드와 다른 상태에 도달한다 (`test_touch`)
3. 고정한 한국어 조사가 단어와 안 맞는다 (`test_hints`)
4. 절차적 배치가 규칙적으로 반복된다 — 다양성 지표는 주기성을 못 본다 (`test_ground`)
5. 상태를 읽는 코드가 상태 기계보다 먼저 돈다 (`test_night`)
6. 셋업 헬퍼가 검사하려는 문제를 미리 해결해 준다 (`test_belt`의 주석)

**새 검사를 넣으면 고치기 전 코드에서 실패하는지 반드시 확인한다.** 양쪽에서 통과하는
검사는 아무것도 증명하지 않는다.

그리고 **왜** 통과했는지도 확인한다. `test_walk`의 중앙 검사는 두 번 공허하게 통과했다 —
한 번은 하루가 끝난 뒤에 봐서 작업 중인 고양이가 하나도 없었고, 한 번은 `place_cat`이
이미 정확히 놓아서 걸어오는 경로가 실행되지 않았다. 검사가 보려는 상황이 실행에 실제로
포함됐는지를 함께 assert한다(`worked > 1000`, `hauled_from_east`).
