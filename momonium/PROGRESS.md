# Momonium 진행 기록 (재개 지점)

자율 개발이 끊겼을 때 여기서 다시 시작한다. 이슈와 이 파일이 원본이며 대화 기억은 원본이 아니다.
매 step이 닫힐 때 갱신한다. 각 step의 커밋 해시는 다음 step에서 채운다(자기 커밋 안에는 적을 수 없다).

## 현재 상태

- 마지막 완료 step: **58** (#58). 다음: 새 이슈(전체 E2E 체크포인트는 Step 60). **속도(Step 58)**: 모든 단계의 작업은 데이터 `seconds` × `balance.pace.work_scale`(2.5), 모모 걸음은 × `travel_scale`(1.3)이고 각각 한 곳에서만 곱한다(`BuildingSystem.stage_seconds`, `MomoSystem.walk_speed`). 테스트가 단계 시간을 데이터에서 셀 때는 `work_scale(sim)`을 곱하고, 산업 규칙 자체를 보는 테스트는 `unit_pace()` 데이터로 돈다. 편지가 오면 그 연구는 바로 발견된다(읽기는 선택, 수락 단계 없음). 연구 버튼의 빨간 점은 '아직 보여 주지 않은 새 주제'이고 연구를 열면 꺼진다(`ResearchSystem.seen`). 모모 머리 위 봉투는 없다. **하늘은 없다**(Step 56) — 화면 전체가 바다이고 하루는 물빛과 물에 비친 흐린 빛으로만 보인다(`design/ART_SPEC.md` §8). 하늘·구름·해·달·별을 다시 그리지 않고, 그런 그림에 미술 크레딧을 쓰지 않는다(주인 결정). 모모는 발보다 0.5 깊이 앞에서 정렬된다(`art.momo_depth`, `design/ART_SPEC.md` §12) — 모모의 노드 위치는 정렬용이고, 서 있는 자리는 `MomoActor.ground()`다. 새 섬은 **모모 0**으로 시작한다 — 모모가 있다고 가정하는 테스트는 `with_starter_momo()`(unit/integration)·`test.use({ starterMomo: true })`(E2E)로 명시한다. 미술 예산은 Step 46부터 이어지는 총 40크레딧 상한을 함께 쓴다(46: 6.20, 51: 7.20, 52: 9.20, 남은 **17.40**)

## 작업 방식 (재개할 때 지킬 것)

1. 이슈 본문을 읽고(`gh issue view <n> --repo 7bvcxz/gamo`) 기존 구현·의존성을 확인한다.
2. 구현 → 새 기능마다 자동 테스트(unit/integration) + E2E 케이스 추가(`tests/e2e/specs/`).
3. `momonium/tools/test.sh`로 unit+integration 전체 실행. 새 E2E 케이스는 **그 케이스만** 단독 확인.
   **전체 E2E 스위트는 Step 10·20·30·40·50 완료 시에만 한 번** (`cd momonium/tests/e2e && npx playwright test`).
4. 리뷰 후 버전 올림: `project.godot`의 `config/version` = `0.<step>.<재배포 횟수>`.
5. `momonium/tools/deploy.sh` → (사이트 변경 시) `cd web && npm run build:pages` → 관련 파일만 커밋 → `main` push.
6. push 후 `momonium/tools/verify_pages.sh`(Pages 반영 대기 → 공개 URL 스모크).
7. 이슈에 한국어 완료 코멘트(구현·변경 파일·추가 테스트·결과·E2E(해당 시)·배포 URL·문제와 해결·제한) → 검증 후 close.
8. 이 파일 갱신 후 다음 step.

다른 게임·`web/`의 다른 페이지는 건드리지 않는다. 커밋 끝에는 세션 attribution 줄을 붙인다.
