# 완전 초기화 (Step 80)

주인은 남은 세이브, 튜토리얼 상태, 실험, 브라우저의 두 번째 저장소 없이 **진짜 새 플레이어**로 플레이테스트할 방법이 필요했다.
설정 화면 맨 아래의 접힌 **고급 / 디버그** 칸에 **모든 데이터 초기화 / 완전 초기화**를 두었다. 지우는 일이라 실수로 한 번 탭해서는 일어나지 않는다.

## 1. 화면: 세 번의 의도

1. 설정 → **+ 고급 / 디버그**를 탭해야 펼쳐진다(기본은 접힘). 안에는 설명 한 줄과 빨간 **완전 초기화** 버튼이 있다. 이 버튼은 묻기만 한다(`SettingsView.reset_requested`).
2. 확인 창(`src/ui/reset_dialog.gd`, 자기 CanvasLayer 90)
   - HUD, 모든 패널, 튜토리얼, 도움말, 선택된 모모의 스케줄 버튼 위에 뜬다. 어둠막이 모든 터치를 받는다.
   - 1단계는 '모든 데이터를 지울까요?'다. 잃는 것(섬·돈·레벨, 고용한 모모와 스케줄, 건물·연구·연구 포인트, 진행 기록, 튜토리얼·도움말·설정, 데모·디버그 상태)과 지우지 않는 것(앱 스토어에서 산 상품, 다른 게임)을 보여 주고, **취소** / **계속** 버튼이 있다.
3. 2단계는 '되돌릴 수 없어요'다. **취소**와 빨간 **모두 지우기**가 있다.
   - 빨간 버튼은 '계속'이 있던 자리가 아니라 그 아래 줄에 있다.
   - 열리고 `ARM_SECONDS`(0.8초)가 지나야 답한다. 그래서 두 번 연속 탭이 두 단계를 다 통과하지 못한다.
- 취소, 어둠막 탭, Esc나 폰의 뒤로가기는 어느 단계에서든 아무것도 바꾸지 않고 닫는다.
- 문구는 영어·한국어·일본어·중국어다(`settings.advanced`·`settings.reset`·`settings.reset_note`, `reset.*`). 폰트 부분집합은 `tools/fonts/build_fonts.mjs`로 다시 만들었다.

## 2. 무엇을 지우나: 한 목록, 한 경로

`src/app/local_data.gd`(`LocalData`)가 이 게임이 기기에 두는 저장소를 **이름으로** 나열하고, 그것만 지운다.

| 저장소 | 이름 |
|---|---|
| 섬 세이브와 그 조각 | `user://momonium_save.json`, `.tmp`, `.bak`, `.corrupt` |
| 세이브의 웹 미러 | localStorage `momonium_save` |
| 설정(언어, 튜토리얼 봤음, 도움말 봤음, 소리, 화면) | `user://momonium_settings.json` |
| 설정의 웹 미러 | localStorage `momonium_settings` |

- 웹의 `user://`는 같은 출처(`7bvcxz.github.io`)의 모든 게임이 함께 쓰는 IndexedDB 하나이고, localStorage도 함께 쓴다. 그래서 데이터베이스·접두어·패턴으로 지우지 않는다. 다른 gamo 게임의 데이터와 엔진 캐시는 건드리지 않는다.
- 안드로이드·데스크톱도 같은 `user://` 파일이다. 웹 미러는 웹에서만 있다.
- **전부 아니면 아무것도.** 먼저 있는 것을 읽어 두고 지운다. 하나라도 지워지지 않으면 이미 지운 것을 그대로 되돌려 쓴다. 그리고 무엇이 실패했는지 확인 창에 빨갛게 적는다('지우지 못했어요: …. 아무것도 초기화하지 않았어요'). 섬은 그대로 계속된다.
- **결제는 초기화 대상이 아니다.** 기기에 결제 기록을 두지 않는다. `PremiumStore`는 스토어에서 검증된 기록만 읽고, 지금은 그런 기록이 없다. 그래서 초기화가 결제를 지우거나 거짓으로 취소하거나 만들어 내지 않는다. 가속기와 광고 제거 자리표시는 초기화로 혜택을 주지 않는다.

## 3. 초기화 순서 (`Main.reset_all_data`)

1. `persist = false`부터 한다. 이후로는 자동 저장, 포커스 잃음, 배경으로 감, 저장 버튼, 섬 판매 무엇도 옛 섬을 다시 쓰지 못한다(모두 `save_now`/`persist`를 지난다).
2. `LocalData.reset`. 실패하면 `persist`를 되돌리고 실패를 알린다.
3. 성공하면 데모(`momonium_demo`)와 판매 넘김(`momonium_handoff`)을 버리고 효과 설정을 되돌린 뒤 장면을 다시 연다.
4. 다음 시작은 세이브가 없는 첫 실행이다.
   - `Simulation.new_island()`: 익은 밭, 시작 돈 $10, 모모 0, 연구 0, Prestige 0.
   - 기본 설정: 언어는 기기를 따르고, 튜토리얼은 다시 할 차례이고, 본 도움말은 없다.
   - 첫 실행 튜토리얼이 스스로 시작한다.
   - 백업 스냅숏을 열지 않는다. 새로고침하거나 닫았다 열어도 새 섬이다.

- 테스트 환경(엔진 meta `momonium_no_save`)에서는 디스크를 건드리지 않고 '저장이 꺼져 있어 지울 것이 없음'이라고 알린다.
- 데모 안에서 초기화하면 플레이어 자신의 세이브와 설정은 지우고 데모에서 나온다. 데모가 쓰지 않는 세이브 경로도 이제 먼저 읽는다. 이전에는 데모에서는 시험용 경로 지정을 무시했다.
- 장면이 바뀌면 `WebLifecycle.detach()`로 페이지 이벤트를 떼어 낸다. 옛 장면을 부르지 않게 하기 위해서이며, 판매와 데모 전환에도 해당한다.
- 테스트용 지름길(확인 건너뛰기, 튜토리얼 건너뛰기)은 만들지 않았다. 브라우저 테스트도 진짜 버튼을 진짜 탭으로 누른다.

## 4. 확인

- `tests/unit/app/test_local_data.gd`
  - 저장소 목록이 이 게임의 이름뿐이고, 패턴·폴더·데이터베이스·결제가 없다.
  - 7개를 다 지우고 다른 게임의 파일·키는 그대로 둔다.
  - 백업·설정 미러·설정 파일 중 하나가 실패하면 나머지가 원래 내용으로 돌아오고, 실패가 보고된다.
- `tests/integration/ui/test_reset_all_data.gd`(실제 게임, 자기 파일)
  - 접힘과 묻기만 하는 버튼.
  - 두 단계 각각의 취소·어둠막·Esc. 무장 전 빨간 버튼.
  - 확인하면 모든 파일이 사라지고, 옛 인스턴스의 저장·포커스·배경·닫기·자동 저장이 아무것도 쓰지 못한다.
  - 다음 시작은 새 설치와 같은 섬·설정이고 튜토리얼이 시작된다. 새로고침해도 그렇다.
  - 저장소 하나가 실패하면 아무것도 바뀌지 않고 실패를 알린다.
  - 테스트의 저장 끔, 데모, 확인 창의 레이어와 터치.
- E2E `tests/e2e/specs/reset80.spec.mjs`(폰, 폰 720×1280, 데스크톱, 진짜 탭)
  - 모모를 선택하고 설정을 스크롤한 상태에서, 1단계 취소와 2단계 취소.
  - '계속'과 빨간 버튼을 0.1~0.3초 안에 이어 탭하면 아무 일도 없다.
  - 확인하면 새 플레이어다($10, Lv 1, EXP 0, 모모 0, 밭 하나, 연구 0, RP 0, 튜토리얼 할 차례, 언어 기본). 다른 게임의 localStorage 키는 그대로이고, 새 탭으로 다시 열어도 새 섬이다.
- 증거: `design/step80/`(720×1280 확인 창 두 단계, 초기화 직후의 섬).
