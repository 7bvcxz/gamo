# 그림과 애니메이션 — 방향과 파이프라인

> Step 03(#96). 무엇을 그리는가, 무엇으로 그리는가, 어떻게 다시 만드는가. 그림은 모두 이 게임을 위해 새로 만든 것이다.

## 지금 게임이 쓰는 그림 — 손으로 쓴 SVG (2026-11-03)

이미지 생성 API가 막혀 있어서(아래 표: OpenAI 크레딧 소진, TopView는 매 호출 사용자 승인 필요) **첫 대표 세트는 SVG로 직접 그렸다.**
벡터라 크기에 상관없이 깨끗하고, 텍스트 파일이라 diff로 고칠 수 있으며, 생성기·크레딧·키잉이 필요 없다. Godot이 import할 때 래스터로 굽는다.

| 파일 | 내용 | import 배율 → 텍스처 |
|---|---|---|
| `assets/art/backdrop.svg` | 잠든 공방 전체(창·달빛·선반·덮인 재봉틀·마네킹·멈춘 큰 시계·커튼·작업대·열쇠 받침 톱니·꺼진 샹들리에·거미줄) | 1.0 → 1440×960 |
| `assets/art/key.svg` | 나비 모양 놋쇠 열쇠 손잡이, 회전축 = 가운데 | 1.0 → 256×256 |
| `assets/art/doll/{head,torso,arm,leg,back_key}.svg` | 인형 컷아웃 리그의 부품. 각 SVG 주석에 피벗 좌표 | 2.0 → 2배(작게 그려도 선명) |

- **깨어남 애니메이션** = `src/view/doll_rig.gd`(`DollRig`): 부품을 피벗에 붙이고 키 포즈 다섯(asleep → stirring → awake →
  stretch → stand, 1.6초)을 보간한다. 눈(감음·반쯤·뜸)은 코드가 그린다. 시간은 `advance(dt)`로만 흐르므로 테스트와 캡처가 정확한
  시각의 포즈를 재현한다. 스토리보드: `evidence/step03/wake_storyboard_zoom.png`(실제 렌더러, 0·0.35·0.7·1.1·1.6초).
- **정령**은 코드로 그린다(빛 번짐 원 + 두 점 눈).
- 고치는 법: SVG를 고친다(Inkscape든 텍스트든) → `godot --headless --path windup --import` → 끝. 부품 크기를 바꾸면
  `tests/unit/test_art.gd`의 크기 표와 `DollRig.PIVOT`을 함께 고친다.

## 이 머신에 실제로 있는 도구 (2026-11-03에 확인)

### 영상 대신 스프라이트

깨어나는 순간은 영상이 아니라 스프라이트로 만든다. 지금은 SVG 컷아웃 리그(위)이고, 래스터 경로에서는 **포즈 네 장의
스토리보드**(한 장의 그림 안에 같은 인형 네 포즈)를 생성해 띠로 자른다. 이유:

- 같은 그림 안의 네 포즈는 따로 생성한 네 장보다 서로 훨씬 닮는다(옷·얼굴·비율).
- 영상 생성은 크레딧이 들고, 주기 찾기·잔재 제거·키 맞추기의 긴 파이프라인이 필요하다(motorio 스프라이트 파이프라인의 교훈들).
  인형 하나의 1.5초짜리 깨어남에는 과하다.
- 비용: 래스터 경로의 원본 세 장은 이미지 API 호출 3번(medium)으로 계획했다. 영상 한 편보다 싸다. SVG 경로는 0이다.

### 읽히는 실루엣

- 인형의 포즈 차이는 **머리 높이와 팔**로 읽힌다(고개 숙임 → 들어 올림 → 똑바로 → 두 팔 위로). 얼굴 표정은 크게 보일 때의 덤이다.
- 열쇠는 두 날개가 비대칭이 아니어야 돌 때 흔들려 보이지 않는다. 몸통 중심을 정사각형의 중심에 둔다(`build_art.gd`).
- 배경은 인형과 열쇠보다 채도와 대비가 낮다(잠든 방). 인형·열쇠가 앞에 선다.

### 프롬프트에 대해 (이 머신의 교훈)

- 없어야 하는 물건은 부정형으로도 이름을 부르지 않는다. 있어야 하는 것만 적는다.
- 배경 그림에는 인형과 열쇠를 넣지 않는다 — 그것들은 게임이 따로 그린다. 그래서 프롬프트에 사람·인형을 부르지 않고,
  열쇠가 꽂힐 자리는 '작업대 위의 작은 놋쇠 톱니 받침'으로 채워 빈자리를 남기지 않는다(빈 사각형은 요청이다).
- 동작은 신체 부위의 위치로 적는다(고개 숙임, 두 팔을 머리 위로).

## 래스터 경로 (생성 그림 — 크레딧이 있을 때)

준비는 끝나 있고 처리 단계는 테스트로 묶여 있다(`test_art.gd`: 초록 키잉, 스토리보드 나누기). 생성만 막혀 있다.
생성 그림을 쓰기로 하면 `build_art.gd`가 만든 `assets/art/*.webp`를 `AtelierView`의 경로 상수(`BACKDROP`, `KEY`)에 걸고,
인형은 `doll_wake.webp` 띠(+JSON)를 프레임 애니메이션으로 쓴다. SVG와 섞어 쓰지 않는다(한 화면에 두 화풍).

```bash
# 1. 초록 참조 캔버스 (art/ref/, 커밋 안 함 — 언제든 같은 것이 나온다)
godot --headless --path windup --script res://tools/art/build_art.gd -- --green
# 2. 원본 생성 — 먼저 dry run(요금 0), 그다음 --go. 있는 파일은 건너뛴다
windup/tools/art/gen_art.sh
windup/tools/art/gen_art.sh --go [backdrop|doll_wake|key]
# 3. 원본 → 게임 에셋 (assets/art/*.webp, doll_wake.json)
godot --headless --path windup --script res://tools/art/build_art.gd
```

- `art/raw/*.png`(원본)는 커밋하지 않는다. 옆의 `*.png.json` 사이드카(프롬프트·모델·참조·토큰)는 커밋한다.
- `build_art.gd`: 초록 키잉 → 디스필 → 작은 조각 제거 → (열쇠) 몸통 중심 정사각형 → 256px / (스토리보드) 빈 열로 포즈를
  나누고 **한 배율**로 줄여 발을 한 줄에 맞춘 띠(셀 200×240) + JSON / (배경) 1440×960으로 채워 자르기 → WebP.
- 게임은 `assets/art/`만 읽는다. **파일이 없으면 Step 02의 도형 그림으로 그린다**(대체 경로, 테스트로 묶음). 그래서 처음 clone한
  상태에서도, 그림을 지운 상태에서도 게임이 열린다.

## 출처와 라이선스

- **지금 게임의 그림(`assets/art/**/*.svg`)은 2026-11-03 Claude Code가 이 저장소에서 직접 쓴 SVG다.** 생성기·스톡·다른 작품의
  참조가 없다. 저장소의 다른 소스와 같은 조건이다(저장소에 별도 라이선스 파일은 없다). 정령과 인형의 눈은 코드로 그린다.
- 래스터 경로로 그림을 만들면: OpenAI 이미지 모델 출력이며(이용 약관상 생성물의 권리는 요청자), 호출 기록은
  `art/raw/*.png.json`과 `imagegen --ledger`, 참조는 단색 초록 캔버스뿐이어야 한다. 그때 이 절을 고친다.
