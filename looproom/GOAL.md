# GOAL : looproom - 좁은 화면 탐험 + 회귀 POC

## 핵심 검증 질문

새 공간을 계속 발견하는 재미와, 잘못된 선택으로 회귀당하는
긴장감이 공존하며 "한 번 더"를 유발하는가?

## 완료 조건 (전부 체크되면 DONE)

* [x] 화면에는 항상 1개의 방만 표시된다 (방 = 고정 크기 그리드)
* [x] 방향키/조이스틱(모바일)로 상하좌우 이동, 방 가장자리를 넘으면 인접한 방으로 전환된다
* [x] 방은 최소 15개 존재하고, 각 방은 색/구조로 구분 가능하다
* [x] 방 중 일부에 "함정 출구"가 있다: 진입 시 시작 방으로 회귀한다
* [x] 특정 방 몇개는 단계적인 입장 순서가 존재. A → 아이템 획득 → B 입장 가능 → C 입장 가능 → B, C 입장 시 D 입장 가능 등등
* [x] 회귀 시 전용 연출(화면 효과 0.5초 이상)이 표시된다
* [x] 함정 출구는 진입 전에 완전히는 알 수 없지만, 최소 1가지 시각적 힌트가 존재한다
* [x] 처음 도달한 방에는 "발견" 표시가 뜨고, 화면 구석에 발견한 방 수 / 전체 방 수가 표시된다
* [x] 모든 방 발견 시 클리어 화면 + 소요 시간 표시
* [x] godot --headless 실행 시 에러 0
* [x] HTML5 export 성공, 모바일 터치로 플레이 가능
* [x] ../motorio의 Grim 캐릭터를 주인공으로 사용

## 하지 말 것

* 절차적 맵 생성 금지 - 15개 방은 손으로 설계된 고정 맵
* 전투, NPC, 스토리 금지
* 방 미니맵 금지 (머릿속으로 지도를 그리는 게 이 게임의 재미 가설)
* 아트는 Grim 캐릭터 외에는 모두 도형 + 색만

## 참고

* Grim 스프라이트는 `motorio/assets/characters/`에 있다.
  `grim_{idle,walk,run,mine}_{s,e,n}.png` 형태이며 **서쪽 시트는 없다** —
  이 저장소의 관례대로 동쪽을 좌우 반전해서 쓴다. 프로젝트가 처음 clone한
  상태에서 실행되어야 하므로 상대 경로 참조가 아니라 `looproom/` 안으로
  복사한다.
* 방 미니맵 금지는 "발견한 방 수 / 전체 방 수" 표시와 충돌하지 않는다.
  숫자는 진행도이고, 금지된 것은 방들의 **배치**를 보여주는 그림이다.
* 함정 출구의 시각적 힌트는 확정적이면 안 된다. 항상 맞는 힌트는 힌트가
  아니라 표지판이고, 그러면 잘못된 선택 자체가 사라져 검증 질문의 절반이
  없어진다.
* 조건에 없는 아이디어가 떠오르면 구현하지 말고 `PROGRESS.md`의 `## 제안`에
  한 줄로 남긴다.
